# /db-migration — Prisma migration bez shadow DB

Automatyzujesz workflow migracji Prisma dla srodowiska BEZ uprawnien CREATEDB.
NIGDY nie uruchamiaj `prisma migrate dev`, `prisma db push`, `pnpm db:migrate`, `pnpm db:push`!

## Zadanie

Utworz migracje: $ARGUMENTS

## Kroki

### 1. Walidacja schema

Sprawdz czy schema jest poprawna:
```bash
npx prisma validate --schema libs/prisma/db/schema.prisma
```
Jesli blad → wyswietl i STOP. Nie kontynuuj z bledna schema.

### 2. Sprawdz migration_lock.toml

```bash
ls libs/prisma/db/prisma-migrations/migration_lock.toml
```
Jesli NIE istnieje:
```
Write libs/prisma/db/prisma-migrations/migration_lock.toml:
# Please do not edit this file manually
# It should be added in your version-control system (i.e. Git)
provider = "postgresql"
```

### 3. Generuj timestamp i folder

Format: `YYYYMMDDHHMMSS_[nazwa_z_argumentu]`
Nazwa: zamien spacje na `_`, lowercase, bez polskich znakow.

```bash
mkdir -p "libs/prisma/db/prisma-migrations/[TIMESTAMP]_[NAZWA]"
```

### 4. Generuj SQL diff

```bash
npx prisma migrate diff --from-migrations libs/prisma/db/prisma-migrations --to-schema-datamodel libs/prisma/db/schema.prisma --script
```

Zapisz output do `migration.sql` w folderze migracji.

### 5. Wyczysc SQL (KRYTYCZNE!)

Przeczytaj wygenerowany SQL i:

**USUN** linie ktore wynikaja z driftu (nie z Twoich zmian):
- `DROP INDEX` dla indeksow ktore istnieja w DB ale nie w schema
- `ALTER TABLE ... DROP COLUMN` jesli to nie Twoja zmiana
- Zmiany w tabelach/kolumnach ktore NIE sa czescia $ARGUMENTS

**SPRAWDZ** czy SQL zawiera:
- Poprawne `CREATE TYPE` dla nowych enumow (z `AS ENUM`)
- `CREATE TABLE` z `DEFAULT uuid_generate_v4()` dla UUID primarow
- `REFERENCES` z odpowiednim `ON DELETE` (SET NULL / CASCADE / RESTRICT)
- Composite indeksy dla typowych query (np. `tenantId + status`)

**DODAJ** jesli brakuje:
- `CREATE EXTENSION IF NOT EXISTS "uuid-ossp"` na poczatku (jesli sa UUID defaults)
- Indeksy na FK kolumnach (jesli nie wygenerowane automatycznie)

### 6. Pokaz userowi wynik

Wyswietl:
- Pelny SQL migracji (po czyszczeniu)
- Sciezke do pliku: `libs/prisma/db/prisma-migrations/[TIMESTAMP]_[NAZWA]/migration.sql`
- Ostrzezenia jesli usunales linie z driftu

### 7. Instrukcje dla usera

```
## Migracja gotowa!

**Plik:** libs/prisma/db/prisma-migrations/[TIMESTAMP]_[NAZWA]/migration.sql

### Wykonaj:
1. Przejrzyj SQL powyzej
2. `pnpm db:migrate:deploy` — aplikuje migracje
3. `pnpm db:generate` — regeneruje klienta Prisma

### Jesli cos poszlo nie tak:
- Sprawdz `pnpm db:migrate:status`
- Popraw SQL recznie i powtorz deploy
```
